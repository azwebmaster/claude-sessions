### Dependency graph

- **008 depends on 005 (hard).** Both plans edit `buildLoadedContext` in
  `server/parser.ts`: plan 005 inserts a `timelineByNodeId` Map near the top
  of the function, plan 008 changes the fallback-id formula a few lines
  further down inside the same function. Executing 005 first means 008's
  diff applies cleanly; executing 008 first would mean 005's insertion needs
  to be rebased around 008's edit. Neither plan's Steps require the other's
  change to already exist — the ordering is purely to avoid an avoidable
  merge conflict in the same function.
- **007 has no hard dependency on 008 (or vice versa), but a soft
  preference to land 007 first.** Plan 007 changes `buildSessionDetail`'s
  subagent-pairing loop; plan 008 changes 4 separate functions elsewhere in
  the same file, including `buildAgentTreeFromEntries`, which is adjacent to
  but not inside the region plan 007 touches. Doing 007 before 008 keeps
  each diff smaller and easier to review in isolation, but there is no
  correctness reason either must precede the other.
- **004 is independent of 003**, but note plan 003 removes the app's one
  `cors()` call site, which is also one of the two `hono` advisories plan
  004's version bump closes. Doing both is correct and not redundant — plan
  004 closes advisories unrelated to CORS too, and plan 003's removal is a
  defense-in-depth change independent of whether the CVE is patched.
- **001, 002, 006** have no dependencies on any other plan in this set.

If executing everything in one pass, the order above (001→008) satisfies
every dependency with zero rework. If time-boxing to just the P1 set, do
001-004 in any order and stop there — nothing in 005-008 blocks on them.

## What's in each plan

- **001** — `ContextChart.tsx`'s tooltip includes billed-but-not-in-context
  output tokens in its composition bar, diluting every percentage; the fix
  is a one-line filter change, paired with new test coverage for
  `buildUsageParts` (which had none). Covers audit findings #1 and #2
  (combined — same root cause, same fix).
- **002** — No CI exists today. Adds a GitHub Actions workflow running
  install → typecheck → test → build on every push/PR.
- **003** — The server's `cors()` middleware allows any origin by wildcard,
  and nothing warns if the server binds to a non-loopback interface. Removes
  the wildcard CORS middleware and adds a startup warning for non-loopback
  binds.
- **004** — `pnpm audit --prod` reports 20 vulnerabilities; two direct
  dependencies (`hono`, `react-router-dom`) account for advisories fixable
  with a pure version bump, no code change.
- **005** — `buildLoadedContext` does an O(n²) linear `.find()` per assistant
  turn to look up a timeline point by `nodeId`, when a precomputed `Map`
  lookup is correct and safe (nodeIds are proven unique within `timeline`).
- **006** — No linter exists today. Adds a flat-config ESLint setup
  (`@eslint/js` + `typescript-eslint` recommended, `eslint-plugin-react-hooks`
  scoped to `src/`), plus the `--fix` pass and manual cleanup needed to reach
  a clean `pnpm lint`.
- **007** — `loadSubagents()` returns subagent transcript files in raw,
  OS-dependent filesystem `readdir()` order, but `buildSessionDetail` pairs
  them to Task-tool nodes (which are in chronological document order) purely
  by array index — so on filesystems/OSes that don't happen to return
  `readdir()` in creation order, subagent trees can attach to the wrong Task
  call. Fixes it by sorting subagent files by first-entry timestamp before
  pairing, with a synthetic-fixture regression test that fails against the
  old code and passes against the fix.
- **008** — The fallback node-id formula `entry.uuid ?? \`assistant-${i}\`` is
  independently retyped in four functions in `server/parser.ts`. Extracts
  one shared `assistantNodeId(entry, assistantIndex)` helper; deliberately
  leaves each function's own `assistantIndex` counter untouched (a smaller,
  lower-risk fix than centralizing the counters too — see the plan's "Out of
  scope" section for why that was considered and rejected).
